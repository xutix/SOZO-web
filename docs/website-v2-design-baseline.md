# SOZO Web V2 设计基线

本文档记录 SOZO Tech 官网 V2 的设计方向、页面结构和代码约束。后续网页 UI、页面模块、素材处理和新增页面，优先遵守本基线。

## 1. 方向选择

- 官网类型：产品发布型官网。
- 首页主角：SOZO Tech 品牌入口，但要为 SOZO Dock 发布和后续产品生态服务。
- 明暗关系：暗色官网骨架 + 亮色产品 / 软件证明物。
- 蓝色使用：极少量，只用于状态点、关键词、导航激活和轻微信号感。
- 图片处理：图片尽量融入背景，避免明显卡片边界。
- 首页内容：极简，只保留品牌主张、Dock、能力入口和联系。
- 导航结构：首页 / 产品 / FPV / 服务 / 支持 / 关于。
- Dock 页面：按产品发布页逻辑讲清楚是什么、材质、功能、App、购买 / 支持。
- FPV 页面：作为工程能力背书页。
- 支持中心：先做轻量入口，后续 Dock 发布时补全下载、手册、更新日志和 FAQ。

## 2. 一句话定位

SOZO 官网 V2 不是“业务堆叠型企业站”，而是“以 SOZO Tech 品牌为入口、以 SOZO Dock 为第一产品、可扩展到产品生态和用户支持的硬件品牌官网”。

## 3. 视觉原则

- 冷静、克制、真实、高级。
- 真实硬件照片优先，不生成错误结构。
- 图片边界用渐变融入背景，不做硬卡片感。
- 不做重赛博，不做满屏霓虹，不做 AI 味很重的虚构硬件。
- 蓝色只做少量信号感，不大面积铺色。
- 同层级页面要有同一套节奏：字号、留白、素材融合、hover、移动端断点保持一致。

## 3.1 视觉参考配方

SOZO Web V2 的参考不是照搬某一个大厂官网，而是组合成一套适合索卓科技的硬件品牌语言。

```text
Linear：30%
Apple：30%
SpaceX / Tesla：30%
Stripe：10%
```

### Linear 30%

用于全站底层气质：

- 冷静、克制、暗色产品感。
- 导航、间距、渐变和动效要轻。
- 页面背景要有“舞台感”，但不能有明显贴图边界。
- 黑色不是纯黑一整块，而是有非常弱的深灰、蓝灰、径向光和层次。

### Apple 30%

用于产品发布页节奏，尤其是 SOZO Dock：

- 大标题、强留白、少文字。
- 产品图、视频和真实证明物优先。
- 功能讲解清楚，但不堆参数。
- Dock 页面要像真实硬件产品发布页，而不是后台控制台或普通企业介绍页。

### SpaceX / Tesla 30%

用于工程现场和真实硬件气质：

- 强调真实产品、现场执行、速度感和工程可靠性。
- FPV、无人机、活动展示、工程现场可以更有力量。
- 只能建立在真实素材上，不生成假的无人机结构、假的 Dock 结构、假的工程零件。
- 画面可以有电影感，但不能变成赛博大片。

### Stripe 10%

只吸收精致层级：

- 柔和渐变。
- 清晰卡片层级。
- 文案和模块组织的细腻度。
- 不采用强 SaaS 风，不把 SOZO 做成软件公司模板站。

### 不采用的方向

- 不走纯 SaaS 官网。
- 不走游戏外设风。
- 不走重赛博、满屏粒子、满屏霓虹。
- 不用 AI 生成错误硬件结构来填画面。
- 不为了炫技牺牲产品理解。

## 4. 页面骨架

```text
首页
产品
FPV
服务
支持
关于

项目现场不作为一级导航，作为关于 / 图集入口承接真实素材。
联系合作不放一级导航，作为页脚 CTA 和页面内入口。
```

## 5. 第一批改造范围

- Header：统一导航、收紧毛玻璃和激活线。
- Brand：Logo 后只保留 SOZO Tech，去掉中文副标题。
- Footer：减少卡片感和硬边界，保持品牌收束。
- Tokens：统一背景、浅蓝强调、线条透明度和文字层级。
- Media：全站图片边界向背景渐变，减少“贴图感”。

## 5.1 第一批 UI 执行优先级

第一批不是大改所有内容，而是先把全站设计系统拉回统一：

1. 统一 Header / Footer / PageHero / CTA 的结构和样式。
2. 统一图片、视频进入背景的方式，去掉明显黑边、硬边框和直角边界。
3. 统一导航文案：`首页 / 产品 / FPV / 服务 / 支持 / 关于`。
4. 统一品牌标识：Logo 后只保留英文 `SOZO Tech`，不再跟中文副标题。
5. 统一蓝色使用：蓝色只做重点字、激活线、状态点和箭头，不做大面积底色。
6. 产品入口 hover 需要有可感知反馈：轻微展开、变宽、变亮或显示二级入口，但保持克制。
7. 移动端优先保证可读和可用，不为了桌面视觉牺牲交互。

## 6. 代码与设计系统规则

这是后续 Codex 写代码时必须遵守的规则。

### 6.1 同层级页面必须共用同一个模块

同层级页面不能各自手写一套“看起来差不多”的结构。品牌官网要有设计系统，同样层级的东西必须共用同一个模块。

- 所有一级页面首屏：统一使用 `PageHero`
- 所有视频首屏：统一使用 `page-hero--video-stage`
- 所有图像首屏：统一使用 `page-hero--image-stage`
- 所有页脚：统一使用 `Footer`
- 所有底部联系入口：统一使用 `FooterCta`
- 所有箭头链接：统一使用 `ArrowLink`

页面可以有不同内容，但不能有不同“脾气”。

### 6.2 差异只能通过参数表达

正确方式：

```jsx
<PageHero
  variant="video"
  page="cases"
  title="..."
  video="..."
/>
```

错误方式：

```jsx
<section className="page-hero page-hero--cases-video">
  ...
</section>
```

后者会让结构、样式、移动端和动效逐渐分叉，是目前页面不一致和 bug 的来源。

### 6.3 统一模块的验收标准

同层级模块必须保持：

- 间距一致
- 字号比例一致
- 视频 / 图片融合方式一致
- 页脚结构一致
- hover 逻辑一致
- 移动端断点一致
- 可访问的链接和交互语义一致

### 6.4 后续重构优先级

下一步最应该做的是一次小型 cleanup：

1. 把 `PageHero` 扩成真正统一的首屏模块。
2. 清掉遗留的重复 CSS。
3. 把 `about` / `cases` / `products` / `fpv` 的首屏都挂到统一接口。
4. 保留页面差异参数，不保留重复结构。
5. 新页面先接入统一模块，再做页面内容。

### 6.5 样式层规则

旧样式文件可以保留历史规则，但新增 V2 级别的全站视觉收敛必须进入独立样式层：

- 新的全站覆盖规则放入 `src/styles/v2-system.css`。
- `src/styles.css` 继续承载历史样式，后续分批删除重复块。
- 不再在任意页面末尾临时追加 page-specific patch。
- 如果一个样式同时影响 Header / PageHero / Footer / CTA，必须先确认它是不是设计系统规则。
- 如果只是单页差异，优先用组件参数或页面 modifier，不复制结构。

## 7. 后续页面策略

- 首页：品牌入口极简化。
- Products：从“产品方向”转为“产品”。
- Cases：从“服务案例”转为“合作服务”。
- Gallery：作为“项目现场”的主入口。
- Support：先建立轻量入口，承接下载、手册、更新日志和 FAQ。
- About：保留团队与品牌可信度，不写成长篇履历。
